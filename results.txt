MPI_Gather on 2D Torus - Simulation Results



Run 1: Naive Gather

Topology: 4x4 2D Torus
Number of nodes: 16
Root rank: 0
Algorithm: naive
Payload size: 1024 bytes
Link delay: 1 ms
Link datarate: 10 Mbps

Results:
Gather completion time: 1.0197344 s
Total hop count: 32
Average latency: 0.00402709 s
Root received packets: 15

Notes:
This is the baseline naive approach. Every non-root node sends its data directly toward the root using shortest-path routing on the 2D torus topology.



Run 2: Optimized / Topology-aware Gather

Topology: 4x4 2D Torus
Number of nodes: 16
Root rank: 0
Algorithm: optimized
Payload size: 1024 bytes
Link delay: 1 ms
Link datarate: 10 Mbps

Results:
Gather completion time: 1.025192 s
Total hop transmissions: 20
Average packet latency at root: 0.004564 s
Root received packets: 6
Root received payloads: 15

Comparison with naive:
The optimized algorithm reduced total hop transmissions from 32 to 20.
The number of packets received by the root decreased from 15 to 6.
However, the completion time slightly increased from 1.0197344 s to 1.025192 s because row leaders wait to collect row data before sending aggregated packets to the root.
For this small 4x4 topology, the optimized method mainly improves network traffic and root load rather than completion time.
